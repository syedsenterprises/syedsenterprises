Graph-First, Reproduce-First: A Small-Model Coding Agent Design for Gemma 4 E4B Under a 12-Hour Budget

Syed Shahed · Syeds Enterprises, Hyderabad, India · Published 25 November 2026 · Open access (CC-BY-4.0)

DOI: 10.5281/zenodo.24538057 · Zenodo record: zenodo.org/records/24538057

Download the PDF Read on Zenodo All research

Abstract

Large language models can write code, but the biggest ones are expensive to run. Small models are cheap and fast, but they fail in ways that are hard to predict. This paper asks whether a small model — Google's Gemma 4 E4B — can be turned into a useful coding agent if the design does the heavy lifting instead of model size. It proposes a graph-first, reproduce-first agent: map the repository as a graph before editing, reproduce the bug before writing a fix, and enforce hard per-task time and token caps. The agent was evaluated on 129 real coding tasks and solved 12 of 129 (9.3%) in 3 hours 34 minutes. The paper reports the failures as carefully as the wins, so the next builder can see exactly where a small-model agent breaks.

Key result

12 / 129 tasks solved (9.3%) in 3h 34m.
Wins by project: FastAPI 7, Rich 4, Requests 1.
Failures: 69 patches failed the tests, 42 execution errors, 4 timeouts, 2 verification failures, 13 no patch.

How the agent works

  • Graph-first localisation. Before touching code, the agent maps the repository as a graph — which files import which, where the relevant functions live — so it edits the right place instead of guessing.
  • Reproduce-first patching. Before writing a fix, the agent reproduces the bug. No reproduction, no patch. This stops the agent from "fixing" things it does not understand.
  • Hard per-task caps. Every task gets a fixed time and token budget, configured in a single file (eval_config.yaml). When the budget runs out, the agent stops. This keeps a 129-task run inside a 12-hour budget.
  • LoRA on its own wins only. Training uses LoRA fine-tuning on the agent's own past successes, and only on public tasks.

Why it matters

If you are building AI tools on a student budget, or deploying them where a large model is not an option, small models are the only choice. This paper is a field report from that constraint: what a 4-billion-parameter model can actually do as a coding agent, measured end to end, with the failures included. The 9.3% result is below the 15.4% figure published for the reference scaffold — the paper is honest about that. The contribution is the design, and a complete failure breakdown the next person can build on.

Context

This paper was submitted to the Paper Track of the Gemma 4 Developer Agent Competition (Google DeepMind / Kaggle). It builds on the author's own agent projects, including the Jarvis Core HUD and a personal RAG system.
